✏️ TP N° 1 — Recordando lo Básico

SELECT · WHERE · ORDER BY · Operadores lógicos (AND, OR, NOT)

Inicial

📖 Mini repaso teórico

Una consulta SQL básica siempre tiene la misma estructura. Pensala como una pregunta en inglés sencillo:

SELECT  columna1, columna2    -- ¿QUÉ querés ver?
FROM    nombre_tabla          -- ¿DE DÓNDE?
WHERE   condicion             -- ¿QUÉ FILTRO?
ORDER BY columna ASC|DESC;   -- ¿EN QUÉ ORDEN?

Operadores de comparación: = igual · != distinto · > mayor · < menor

Operadores lógicos: AND (ambas condiciones verdaderas) · OR (al menos una) · NOT (niega)

💡 Tip: Los textos en WHERE van entre comillas simples ('Posadas') y los números sin comillas (precio > 100000).

📊 TP N° 2 — Funciones de Agregación

COUNT · SUM · AVG · MAX · MIN · GROUP BY · HAVING

Intermedio

📖 Mini repaso teórico

Las funciones de agregación calculan un único resultado a partir de varias filas:

COUNT(*)           -- Cuenta cuántas filas hay
SUM(precio)        -- Suma todos los precios
AVG(precio)        -- Calcula el promedio
MAX(precio)        -- Devuelve el valor más alto
MIN(precio)        -- Devuelve el valor más bajo

-- Con GROUP BY agrupamos por categoría:
SELECT id_categoria, COUNT(*) AS cantidad
FROM productos
GROUP BY id_categoria
HAVING COUNT(*) > 3;
⚠️ Diferencia clave: WHERE filtra FILAS individuales (antes de agrupar). HAVING filtra GRUPOS (después del GROUP BY).

🔗 TP N° 3 — Relacionando Tablas con JOINs

INNER JOIN · LEFT JOIN · Consultas multitabla

Interm. Alto

📖 Mini repaso teórico — ¿Qué es un JOIN?

Las tablas están conectadas por claves foráneas (FK). El JOIN es el comando para unir sus datos en una sola consulta, como si juntaras dos hojas de cálculo por una columna en común.

⚡ INNER JOIN

Solo devuelve filas que tienen coincidencia en AMBAS tablas. Si un producto no tiene proveedor, no aparece.

⬅️ LEFT JOIN

Devuelve TODOS los registros de la tabla izquierda (FROM). Los que no tienen coincidencia aparecen con NULL.

-- INNER JOIN: producto + su categoría
SELECT p.nombre, c.nombre AS categoria
FROM productos p
INNER JOIN categorias c ON p.id_categoria = c.id_categoria;

-- LEFT JOIN: todos los clientes (tengan o no ventas)
SELECT c.nombre, c.apellido, v.fecha_venta
FROM clientes c
LEFT JOIN ventas v ON c.id_cliente = v.id_cliente;
💡 Truco: Poné alias cortos a las tablas (p para productos, c para clientes) y escribí el campo como tabla.columna. Así evitás errores de ambigüedad.

🏆 TP N° 4 — El Desafío Profesional

Subconsultas · JOIN + GROUP BY + HAVING combinados

Avanzado

📖 Mini repaso teórico — Subconsultas

Una subconsulta es una consulta SQL escrita dentro de otra. MySQL la ejecuta primero y usa el resultado como si fuera un valor o una tabla temporal.

-- Subconsulta: productos más caros que el promedio
SELECT nombre, precio
FROM productos
WHERE precio > (SELECT AVG(precio) FROM productos);

-- Combinado: JOIN + GROUP BY + HAVING
SELECT c.nombre, SUM(dv.precio_unitario * dv.cantidad) AS total
FROM clientes c
INNER JOIN ventas v ON c.id_cliente = v.id_cliente
INNER JOIN detalle_ventas dv ON v.id_venta = dv.id_venta
GROUP BY c.id_cliente
HAVING total > 500000;
🧠 Estrategia: Dividí el problema. Primero identificá las tablas (JOINs), después qué calculás (agregación), luego el filtro (HAVING o subconsulta).
